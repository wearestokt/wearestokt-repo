# Toolcraft Agent Worklog

## Status

Mode: product

Product: Flow Field — an art-directable vector-field graphic generator that
produces still PNG/JPG/SVG output of directional markers over a procedurally
generated flow field, inspired by scientific ocean-current charts but fully
art-directed.

## Decisions

Build a Canvas 2D custom renderer driven entirely by Toolcraft schema controls.
Still output only (PNG + clipboard copy); no animation, timeline, or layers. The
flow field is generated by a pure, shared math module so the live preview and the
PNG export draw identical vector output. See `specs/flow-field.md` for the full
Renderer Technique Decision Matrix, Renderer Layer Inventory, and Render Pipeline
Inventory.

## Decision Trail

### Iteration 1 — Product build

- Request: Build a tool to create "flowy current flow" graphics that resemble
  scientific ocean-current data but are far more art-directable, for graphic
  creation.
- Task type: New product app (custom renderer).
- User-visible result: A flow-field canvas of directional markers (wedge, arrow,
  line, dart) on an editable-output canvas, controlled by pattern, direction,
  frequency, swirl, turbulence, grid density, jitter, marker size/color, and
  background, with Export PNG / Copy PNG.
- Source/reference checked: User-provided still reference images of arrow/triangle
  vector fields and ocean-current plates (static images, not video).
- Reference inputs: Six still PNG references of directional vector-field artwork
  and current charts; no motion/video reference, so no Video Reference Study is
  required.
- Docs/contracts read: `docs/toolcraft/workflow.md`, `assembly-workflow.md`,
  `schema-reference.md`, `renderer-technique.md`, `component-rules.md`,
  `acceptance-testing.md`, `performance.md`, `decision-contract.md`,
  `custom-controls.md`, plus runtime export/state/schema types.
- Contract rules applied: runtime-shell-required, canvas-no-app-ui,
  canvas-surface-preserved, controls-product-coverage, output-export-required,
  renderer-technique-inventory, performance-coverage-levels,
  acceptance-product-observable, persistence-policy-explicit, controls-layout-heuristics.
- Decision: Canvas 2D vector-output renderer; field-sample pass cached, glyph-draw
  pass re-rasterizes on style change; zoom/pan handled by canvas shell CSS
  transform; PNG export reuses the shared draw at the selected image resolution.
- Alternatives rejected: SVG/DOM glyph nodes (layout/GC pressure, slow export);
  WebGL/WebGPU (overkill for static vector fills, harder pixel-accurate export);
  animation/timeline (out of scope for still graphic creation).
- State/output mapping: `flow.*`, `field.*`, `marker.*`, `appearance.background`,
  `export.includeBackground`, `export.image.*` runtime values feed
  `readFlowFieldSettings` → `buildFlowGlyphs` → `drawFlowField` for both preview and
  export.
- Files changed: `src/app/flow-field-math.ts`, `src/app/flow-field-renderer.tsx`,
  `src/app/app-schema.ts`, `src/routes/index.tsx`, `src/app/app-acceptance.ts`,
  `src/app/app-performance.ts`, app + e2e tests, `specs/flow-field.md`.
- Verification: `pnpm verify:final` passed; agent browser checks of controls,
  export, and viewport stability; browser performance checkpoint recorded below.
- Skipped checks: none.
- Risks: Glyph count scales with density × canvas area; bounded by density hard
  limit and field-sample caching.

### Iteration 2 — Spline guides, linear mask, SVG export

- Request: Draw adjustable spline guides that bend nearby flow by proximity and
  influence; optionally hide uninfluenced markers for linear compositions; export SVG.
- Task type: Product feature iteration (renderer + export + canvas handles).
- User-visible result: Flow Guides section (Edit guides, Influence, Reach, Linear
  only, Add/Delete path), canvas spline overlay, guide-bent field, SVG format option.
- Source/reference checked: User follow-up on the Flow Field product build.
- Reference inputs: Prior still vector-field reference plates; no new motion reference.
- Docs/contracts read: `docs/toolcraft/custom-controls.md`, `component-rules.md`,
  `renderer-technique.md`, `acceptance-testing.md`, `performance.md`.
- Contract rules applied: canvas-handle-placement (guide overlay in product output),
  controls-product-coverage, output-export-required, renderer-technique-inventory,
  acceptance-product-observable, performance-coverage-levels.
- Decision: Catmull-Rom guide sampling in `flow-guide-math.ts`; per-glyph guide weight
  drives angle blend and optional linear cull; SVG export as app-owned vector builder
  sharing glyph instances with Canvas 2D; guide overlay excluded from all exports.
- Alternatives rejected: Bezier handles (more complex UX); soft opacity feather
  (hard cull chosen for clear linear ribbons); runtime SVG helper (none exists).
- State/output mapping: `guides.*` values feed `readFlowGuideSettings` →
  `buildFlowGlyphsForState` (scales paths at export resolution) → `drawFlowField` /
  `buildFlowFieldSvg`.
- Files changed: `flow-guide-math.ts`, `flow-guide-overlay.tsx`,
  `flow-field-svg-export.ts`, renderer/schema/routes/acceptance/performance/tests.
- Verification: `pnpm verify:quick` + targeted browser acceptance for guides and SVG;
  full browser performance checkpoint not re-run for this post-first-working feature pass.
- Skipped checks: none.
- Risks: Guide nearest-point query is O(glyphs × segments); acceptable at current density caps.

## Renderer

- Decision: Canvas 2D custom renderer with a cached field-sample pass and a
  glyph-draw rasterize pass; shared `drawFlowField` for preview and export.
- Reason: vector-output of thousands of small polygons is fastest and most
  export-faithful in Canvas 2D; preview/export parity is guaranteed by reuse.
- Evidence: `src/app/flow-field-renderer.tsx`, `src/app/flow-field-math.ts`,
  `app-performance.ts` `rendererTechnique`/`rendererPipeline`, `specs/flow-field.md`.

## Timeline

- Decision: No timeline; `panels.timeline` omitted.
- Reason: Still-image graphic tool with no animation or video export.
- Evidence: `src/app/app-schema.ts` (no timeline), `specs/flow-field.md` scope.

## Layers

- Decision: No layers panel; single product-foreground glyph layer only.
- Reason: One vector output layer over an optional flat background fill; no
  multi-layer compositing or per-layer editing.
- Evidence: `app-performance.ts` `rendererTechnique.layers` (single
  product-foreground layer), `src/app/app-schema.ts`.

## Controls

- Decision: Schema-driven sections — Flow Field, Flow Guides, Field Grid, Marker Style,
  Background, Image Export, plus sticky Export actions.
- Reason: Controls grouped by product meaning (field equation, grid, glyph,
  background, export) per controls-layout heuristics; all built-in controls.
- Evidence: `src/app/app-schema.ts`, `src/app/app-acceptance.ts`
  `starterControlSectionInventory`, `specs/flow-field.md` Control Selection Inventory.

## Export

- Decision: Sticky `Export PNG` and `Copy PNG`; `Image Export` Format/Resolution
  selects PNG/JPG/SVG; required `Background` section with Include + unlabeled color.
- Reason: output-export-required; raster formats use `createToolcraftPngExportCanvas`;
  SVG uses `buildFlowFieldSvg` at the selected resolution.
- Evidence: `src/routes/index.tsx` `handlePanelAction`, `src/app/app-schema.ts`
  Image Export + Background sections.

## Performance

- Decision: 26 scenarios — every control plus preview-render, viewport-stability,
  viewport-zoom stress, export-copy, guide drag/mask, and export-svg; `field.density` and
  `export.image.resolution` are workload with large-canvas baselines.
- Reason: performance-coverage-levels requires workload + responsiveness coverage;
  density and export resolution drive the heaviest rasterization.
- Evidence: `src/app/app-performance.ts`, `e2e/app-performance.spec.ts`.
